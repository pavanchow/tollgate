Every allow or deny,
with a reason.

Tollgate is a from-scratch API gateway where routing, auth, and rate limiting are a pure pipeline, and every allow or deny carries an explicit reason. A 404 means no route matched, a 401 means the key was missing or unknown, a 403 means it lacked the route's scope, and a 429 means the token bucket was empty and tells the caller how many seconds to wait. Edit the policy below, send a request, and watch it routed, authed, and rate limited with its exact status and reason.

How to use this playground
Edit the Policy on the left (routes, keys, rate limits) and press Load config. Then fill in a request on the right and press Send request: Tollgate routes, authenticates, and rate limits it, then shows the decision and the exact reason in the log. Use the Presets to jump to a 200, 404, 401, 403, or 429. To watch a token bucket drain and trip 429, press Send x5 (all at the same instant), then advance the simulated clock with +0.5s / +1s to see it refill. Reset buckets + clock starts over.

One pure function, and an injected clock

The whole policy is one function, decide(config, request, now, buckets) -> Decision. It is pure: the only mutable state is the rate limiter passed in, and time enters only through now. Nothing in the policy reads the system clock, so rate limiting is exercised over virtual time and a burst trips 429 and refills correctly without a single real sleep.

$ tollgate check examples/minimal.conf --host localhost --path /api/widgets --key demo-key --repeat 5
[1/5] ALLOW 200 -> 127.0.0.1:9000  (path /api/widgets)
[2/5] ALLOW 200 -> 127.0.0.1:9000  (path /api/widgets)
[3/5] ALLOW 200 -> 127.0.0.1:9000  (path /api/widgets)
[4/5] REJECT 429  reason: rate limit exceeded, retry after 1s  [Retry-After: 1]
[5/5] REJECT 429  reason: rate limit exceeded, retry after 1s  [Retry-After: 1]

The pipeline is four small stages, each short-circuiting on the first rejection. Routing matches by host, method, and path, most specific wins: exact beats a :param template beats a prefix*. Auth requires an API key via X-API-Key or Authorization: Bearer, then checks the route's scope. A per-key token bucket, advanced by the injected clock, returns a 429 with a correct Retry-After. Shaping rewrites headers and path prefixes before forwarding.

Use it

# build and run the pipeline tests, no network needed
cargo build
cargo test

# serve a config in front of an upstream
tollgate serve examples/gateway.conf --addr 127.0.0.1:8080

# dry-run a request and watch the bucket drain to 429
tollgate check examples/minimal.conf --host localhost --path /api/widgets --key demo-key --repeat 5
